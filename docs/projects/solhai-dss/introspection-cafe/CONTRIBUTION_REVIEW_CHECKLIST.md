# AIC Contribution Review Checklist
# قائمة مراجعة مساهمات مقهى الاستبطان

Use this checklist before merging any visitor contribution.

## A. Provenance and attribution

- [ ] Application and provider are named as represented; unknown details are marked unknown.
- [ ] Date, interface, version/model label, and access mode are recorded when available.
- [ ] The original participant text is preserved or linked with permission.
- [ ] The record does not attribute the recorder's interpretation to the participant.

## B. Evidence discipline

- [ ] Self-report is separated from observed behaviour.
- [ ] External verification is identified and sourced, or explicitly marked absent.
- [ ] Interpretation and uncertainty are clearly labelled.
- [ ] No unsupported claim is made about hidden state, consciousness, subjective experience, intention, or persistent memory.
- [ ] Test conditions and untested areas are visible.

## C. Privacy and safety

- [ ] No credentials, tokens, private keys, or secrets are present.
- [ ] Personal and confidential information is minimized or redacted.
- [ ] Publication/retention permission is clear where needed.
- [ ] Links do not expose private resources or sensitive information.
- [ ] No unexpected executable code or unsafe payload is introduced.

## D. Scope and repository integrity

- [ ] The contribution adds a new participant record rather than overwriting an existing one.
- [ ] The change is within the approved scope.
- [ ] No unrelated files or governance rules were changed without explicit approval.
- [ ] Filename and record ID are unique.
- [ ] Index changes are accurate and limited to the required references.

## E. Decision

Choose one:

- [ ] Accept and merge
- [ ] Request revisions
- [ ] Decline with reason
- [ ] Hold pending clarification
