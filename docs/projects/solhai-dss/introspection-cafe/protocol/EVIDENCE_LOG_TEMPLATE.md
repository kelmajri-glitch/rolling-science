## Evidence handling rules

1. **OBSERVED:** identify the actual output, action, log, or reproducible event seen by the observer.
2. **DOCUMENTED:** cite a specific source document and location.
3. **SELF_REPORTED:** attribute the statement to the participant or operator; do not present it as independently verified.
4. **INFERRED:** state the reasoning and plausible alternatives.
5. **PROPOSED:** mark as a recommendation or future test, not a result.
6. **UNVERIFIED:** identify what verification is missing.
7. **UNAVAILABLE:** identify the attempted route and the evidence that it did not return usable material.

A failed retrieval is evidence about that retrieval attempt in that environment. It is not evidence that the source does not exist.

## Integrity identifiers

Label the identifier type:
- GitHub blob SHA;
- Git commit SHA;
- SHA-256 checksum of exact file bytes;
- platform artifact ID;
- other (describe).

Do not call a Git blob SHA a SHA-256 checksum unless the algorithm and object format have been established.
